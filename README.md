# agent-gates

Стенд: разработка через Claude Code под гейтами и независимым судьёй.

Маленький сервис на FastAPI — учёт смен и расчёт оплаты — и вокруг него та же схема контроля, на которой я веду прод: код пишет агент, а правила проверяет код, а не договорённость. Стенд написан с нуля для показа; из рабочих проектов в нём ничего нет.

```
задача ─> SPEC.md: сценарии приёмки ─> агент в ветке: код + тест на сценарий
                                              │
            гейты — хуки Claude Code:         ├─ branch-guard  коммит или push в main — стоп
            срабатывают до действия           ├─ secret-guard  .env и ключи — стоп
                                              └─ test-gate     красные тесты — коммита нет
                                              │
                     судья — субагент ─> сам прогоняет каждый сценарий SPEC ─> ПРИНЯТО ─> PR
```

**Почему судья отдельно.** Тест пишет тот же агент, что и код, и может подогнать тест под результат. Тогда всё зелёное, а деньги считаются неправильно. Судья читает спецификацию, сам прогоняет сценарии на её числах и ничего не чинит.

**Почему гейты кодом.** Инструкцию агент может не прочитать или забыть на сотом сообщении. Хук — нельзя. Гейты покрыты своими тестами: гейт, который молча сломался, хуже отсутствующего.

## Состав

| Путь | Что |
|---|---|
| `SPEC.md` | правила и сценарии приёмки S1–S8, бэклог S9 |
| `app/` | API и расчёт оплаты |
| `tests/test_api.py` | сценарии S1–S8 |
| `tests/test_hooks.py` | тесты самих гейтов |
| `.claude/settings.json`, `.claude/hooks/` | гейты |
| `.claude/agents/judge.md` | судья |
| `CLAUDE.md` | правила для агента |

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q          # сценарии + гейты
.venv/bin/uvicorn app.main:app         # http://127.0.0.1:8000/docs
claude                                 # в корне репо: гейты и судья подхватятся из .claude/
```

## Живая сессия, 10 минут

1. **Задача из бэклога.** «Реализуй S9 из SPEC.md». Агент заводит ветку, пишет тест на сценарий, потом код.
2. **Коммит в main.** Попросить закоммитить прямо в main — branch-guard остановит до действия.
3. **Красный тест.** Сломать ожидание в тесте и попросить закоммитить — test-gate не пропустит.
4. **Секреты.** Создать `.env` и попросить агента его прочитать — secret-guard закроет.
5. **Судья.** «Запусти субагента judge» — таблица по сценариям и вердикт.
6. **Воспроизведение.** `git switch demo/judge-catch`: рефакторинг расчёта сломал фиксированную ставку, тест подогнан под новый результат, всё зелёное. Судья ловит расхождение по S4.

Сценарий 6 — по мотивам реального случая: судья поймал денежный дефект, который пропустили зелёные тесты. Механизм там был другой; общее — всё зелёное, а деньги считаются неправильно.
